# qywork

qywork 是一个**本地优先的开源编码 Agent**。它把一次编码需求组织成完整的任务闭环：
理解项目、规划步骤、读取和修改代码、运行命令、验证结果，并把全过程保存下来。

它不是给聊天模型套一层界面，也不是云端开发环境。它的核心是运行在用户电脑上的任务执行内核；
桌面端、命令行和手机浏览器只是访问同一份本地状态的不同入口。

## 产品定位

普通对话模型擅长回答问题，但真实的软件任务还需要处理工作区、工具调用、执行状态、失败恢复和历史记录。
qywork 负责把这些环节连接成一条可持续运行、可追踪、可恢复的业务链。

用户只需要提供三样东西：

- 一个本地项目目录；
- 一项需要完成的任务；
- 自己选择的模型接口和 API Key，或一个本地模型服务。

qywork 负责维护任务上下文，驱动模型使用工具，并将每一步执行结果带回下一轮判断，直到任务完成或明确停止。

## 核心业务闭环

```text
用户提出任务
    ↓
确定工作区与会话
    ↓
创建一次独立运行
    ↓
组装上下文、工具与权限边界
    ↓
模型判断下一步动作
    ↓
读取文件 / 修改代码 / 搜索内容 / 运行命令
    ↓
记录结果并反馈给模型
    └──────── 未完成：继续下一轮
    ↓
输出结论，保存过程、状态与用量
```

这条闭环由五类核心对象组成：

| 对象 | 负责什么 |
|---|---|
| 工作区 | 对应一个本地项目目录，是文件和命令执行的边界 |
| 会话 | 保存用户与 Agent 的连续上下文，可以承载多次任务 |
| 运行 | 对应一次具体任务，从开始、执行到完成或失败都有明确状态 |
| 步骤 | 保存模型正文、思考过程和每一次工具动作，供实时展示与历史回放 |
| 用量账本 | 按模型、工作区和时间记录请求用量，不依赖会话是否保留 |

例如，用户要求“修复登录错误并补充测试”时，qywork 会在指定工作区中读取相关代码，
让模型提出修改，执行文件操作与测试命令，再把测试结果交回模型继续判断。
整个过程不是一条临时聊天记录，而是一项有状态、有结果、可以复查的运行。

## 系统结构

```text
Tauri 桌面端 ── WebSocket ─┐
手机浏览器 ─── WebSocket ──┼──> qy serve 本地服务 ──┐
                                                      ├──> Runtime / Agent Loop
qy exec 命令行 ───────────────────────────────────────┘          │
                                                                 ├── 模型适配器 ──> 用户配置的模型服务
                                                                 ├── 工具与权限 ──> 本地工作区
                                                                 └── 持久化 ──────> SQLite 本地账本
```

`qy` 是产品内核。桌面端由 Tauri 启动 `qy serve`，WebView 通过本地 HTTP 和 WebSocket
读取业务数据；手机端在用户明确开启局域网访问后连接同一个服务；`qy exec` 则直接复用相同的
运行时完成单次任务。

业务状态只由本地内核维护，前端负责展示和发送指令，不另外保存一套会话或运行状态。
因此桌面刷新、WebSocket 重连或切换入口时，看到的仍是同一份任务记录。

## 核心能力

- **本地任务执行**：围绕真实工作区读取、搜索、编辑文件并运行项目命令。
- **多模型接入**：支持 Anthropic、OpenAI 兼容接口、OpenAI Responses 和本地模型端点。
- **持续 Agent 循环**：模型根据工具结果继续判断，而不是只生成一次性代码片段。
- **过程持久化**：会话、运行、步骤、工具结果和用量写入本地 SQLite，支持回放和恢复。
- **上下文管理**：长会话可以压缩后继续执行，原始记录仍保留在本地账本中。
- **多入口协同**：桌面端、CLI 和可选的手机端共享同一个内核与协议。

技能、记忆、MCP、插件、定时任务和多 Agent 编排属于扩展层。它们可以增加工具与自动化能力，
但不会改变上面的核心业务闭环。

## 数据与权限边界

- qywork 不要求注册账号，不提供 qywork 云同步，也不采集产品遥测。
- 配置、会话、运行记录和用量账本保存在本机 `~/.qywork/`。
- API Key 保存在本机配置中；模型请求发送到用户自己配置的服务商或本地端点。
- 桌面端默认只连接本机服务；手机接入需要用户主动开启局域网监听并完成配对。
- Agent 可以修改文件和运行命令，因此它不是只读聊天工具。原生 Windows 当前没有内核级命令沙箱，
  权限模式和平台边界请先阅读 [权限说明](docs/permissions.md)。

## 快速开始

从源码运行需要 [Bun](https://bun.sh)，具体版本以根目录 `package.json` 为准。

```bash
bun install
bun run packages/cli/src/index.ts init
bun run packages/cli/src/index.ts exec "阅读当前项目并说明它的核心结构"
```

启动桌面开发环境：

```bash
bun run tauri:dev
```

构建桌面安装包：

```bash
bun run tauri:build
```

## 代码分层

| 目录 | 职责 |
|---|---|
| `apps/web` | 桌面与手机共用的 Web 界面 |
| `apps/desktop` | Tauri 桌面外壳、Sidecar 生命周期与本地终端 |
| `packages/cli`、`packages/server` | 命令入口、本地 API 与 WebSocket 服务 |
| `packages/runtime`、`packages/agent` | 会话装配、上下文管理和 Agent 执行循环 |
| `packages/tools` | 文件、搜索、命令、网络等内置工具及权限边界 |
| `packages/ai` | 不同模型协议的统一适配层 |
| `packages/store`、`packages/core` | 业务对象、事件协议、SQLite 账本与正文存储 |
| `packages/mcp`、`packages/plugins`、`packages/team` | 可选扩展能力 |
