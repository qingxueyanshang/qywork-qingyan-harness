画布生成卡发送前，`compilePrompt` 把手写的素材编号（「@图片1」「图片1」「@Image1」等）按所选型号登记的写法改写，编号不变；卡片上的提示词与文本卡文件不改写。改写必须可见：`CanvasView.relabels` 逐卡列出「原文→发送」，读取画布与修改回执中写为「发送时改写」，生成面板提示词下方显示同一行，文本标签的预览按 `view.mentions` 显示改写后发送的文字。三处与发送共用 `relabelInputs`，不另写规则。

**Why:** 2026-10-21 加入过不可见的改写，用户以「看不见的转化，没啥用」否决并撤回。2026-10-31 用户给《B面留给你》换到 hongcheng 时，制作脚本中的 418 处「@图片N」须逐处改写，用户认为依赖技能改写有缺陷，选择由画布改写，条件是「ai会告知，提示词面板能实时看到更新的就ok吧」。

**How to apply:** 不要撤去 `relabels` / `mentions` 与面板的显示而只保留改写；不要恢复按写法拒绝运行。未登记写法的型号（如木木）按原文发送，改写无法覆盖，需实际提交一次确认写法，见 [[relay-catalog-no-mention-syntax]]。素材芯片 `@[卡片]` 按型号写法编号属于既有设计。
