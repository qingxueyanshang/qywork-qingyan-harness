发给模型的上下文只有压缩一个入口可以改变：占用到阈值时自动压缩，或用户手动压缩，两者经同一入口、界面可见。
不要提议在压缩之外另加规则改写历史内容，例如「同一标签页已有更新观察时，旧元素列表只保留一行」。

**Why:** 2026-11-17 助手提出上述规则，用户否决：「到 80% 会自动压缩，要么就是用户手动压缩，你去动上下文做什么，凭什么能做」。
核对后该规则本身不成立：
- 它是与压缩并列的第二个改写入口，每次请求都生效且界面不可见，属于 CLAUDE.md A2 默认否决的并列执行入口；
- 前提错误：新观察使旧列表的元素编号失效，内容并未失效。元素列表是页面显示内容的唯一记录，跨页核对的取值、动作前后的比较都依赖它。

**How to apply:** 上下文大导致慢或费用高时，只报告事实（占用量、各类内容占比、等待时间与上下文大小的关系）；
上下文大小随用户设定的压缩阈值变化，不作为缺陷处理。修复方向放在调用次数与工具返回的事实上（减少无效调用、尽早发现无效操作）。
