模型绕行完成任务（例如操控 qywork 自身界面打开画布、等待生成、导出时间线）时，修复的对象是使它只能绕行的缺陷：缺少的工具能力、
无法看到动作结果的投递方式、界面缺少的辅助功能标记。不在系统提示或工具说明中添加「不要做 X」「X 只用于 Y」之类的限制。

**Why:** 2026-10-29 方案中写入「电脑控制只用于 qywork 以外的软件」，被用户否决：这是纯限制，确有需要时会误导模型，且缺陷仍在。
用户的要求是「解决为什么会去电脑控制的问题，修复的是不去控制的缺陷」。

**How to apply:** 先在账本中取得模型绕行前的第一步（常见情形是先尝试了某个工具、发现无法完成）与思考原文，据此定位缺失的能力；
方案中把每一处绕行对应到一个能力缺口或缺陷。工具说明只陈述能力与用法，不写针对某一错误行为的禁令。与 [[canvas-prompt-no-hidden-rewrite]] 同属「修复源头」一类。
